# Bloom architecture

The product has two compile-time native layouts: author and chat. Rust derives their panes and toolbar controls together. Both use the same ordinary file workspace. Author imports capture folder structure and original bytes; no ordinary-file writeback exists. Live search reads captured document bodies off the UI thread and binds highlight ranges to the query and source revision. Swift owns AppKit/SwiftUI, Foundation file storage, AVFoundation/Speech and MLX integration. New validation and request-planning policy lives in the safe Rust `bloom-core` crate. A single Cargo workspace also contains the attachment inspector and its narrow C bridge.

## Captured authority

A Voice is independent of a model: stable UUID, unique mention name, display name, instructions, ordered examples and immutable content revision. A send captures the selected revisions, model, question, history, sources and speaker names. Historical attribution does not consult the mutable voice library. Rust treats another voice's contribution as explicitly attributed content, rather than silently turning it into the current voice's assistant response.

Separate answers share the captured history and question. Discussion additionally supplies completed earlier responses from that round. There are at most three voices. Ask has no edit authority. Propose requires acceptance. Edit is limited to one captured voice and the granted document revision. Rust compiles explicit read-only or revision-bound tool permission into every consultation. Rust also parses whole-response edit JSON and validates exact, nonoverlapping Unicode anchors; Swift commits the accepted result through the native editing owner and immutable source publication. Sources are revalidated against the live editor generation and captured file revision before an edit is committed. A response cannot become complete before its patch is validated and any authorized automatic commit finishes.

## Authored continuation

A CompletionRecipe captures manuscript UUID/revision and snapshot, UTF-16 cursor, chosen examples in order, exact prompt and digest, omitted prefix count, model identity, profile and output budget. Rust rejects cursor positions inside a Unicode grapheme. Examples contribute their prose; the prompt has no chat instructions or technical source headings. Text after the cursor is excluded.

CandidateBundle records retain recipes, seeds, actual outputs, token IDs, terminal state and branch origin. Automatic suggestions produce one candidate capped at 64 tokens. Explore shares one prefill across three independently seeded batch rows, each capped at 256. Only explicit acceptance changes the manuscript. Branching uses the captured snapshot, retains following text, and records the original document/revision and candidate identity. Editing, moving the cursor, changing examples and composition invalidate acceptance of old results. Native Undo owns accepted insertions.

## Model and generation ownership

The signed catalog binds local converted packs and pinned public source checkpoints to expected hashes. Cache discovery is separate from admission: a file's presence does not prove integrity or residency. Public snapshot links resolve only within that snapshot or its corresponding blob store; configuration lookup and complete file verification share that path policy. Converted packs require regular files. Startup automatically reuses verified local packs or installs pinned public snapshots anonymously with resumable transfers and hash verification. Generation uses admitted local files. Conversion is a developer executable rather than an installation dependency.

GenerationCoordinator serializes model loading and GPU generation. Cancellation retains ownership until the producer is joined. Foreground requests cancel background suggestions. UI callbacks capture cancellation/operation identity, candidate identity and editor epoch. Model identity and available memory determine context admission; architecture's advertised context is not a promise that it fits.

## Durable file state

WorkspaceStore is an actor. `workspace.json` retains metadata, chats and drafts; `identity.json` identifies the workspace. The existing Vault serializes ordinary object-record access and atomic replacement, with regular-file and bounded-read admission. No application encryption key, Keychain access, database or old-format migration is required. One process holds the workspace file lock until its source engine closes.

Manuscripts use immutable UTF-8 pages and per-document source/history roots. The logical editor accepts input into bounded resident windows and Foundation Undo immediately. Saved publication and its acknowledgement run independently; receiving an older saved checkpoint cannot replace the live source, input client or current selection. Read-only viewport movement does not join persistence. Complete roots and native history groups support selections and Undo across windows without assembling the whole file. Imports, exports and search stream bounded chunks.

Generation checkpoints retain attempt identities, speakers, token/output progress and captured sources. Reopening validates retained records and marks interrupted attempts cancelled while preserving available partial output. Malformed metadata, missing pages and invalid source/history roots are failures; they never admit an empty replacement workspace. Process-interruption handling is distinct from a power-loss guarantee.

Unsent composer text and its ordered attachments belong to a conversation UUID, or to a manuscript UUID before a conversation exists. These optional fields and the ordered writing-example selection are retained in workspace metadata, included in complete backups, and validated before use. Switching owners restores that owner's draft and returns to Ask. Consultation mode is not retained across switching or restart; consecutive sends within the active conversation keep the selected mode. Opening a workspace never sends retained text or starts a writing exploration. Intentional sending clears only the sent draft; deletion discards drafts belonging to the explicitly removed owner.

Complete backup joins preceding saves, exports and generation producers, then captures a consistent native file clone under the existing source writer queue and metadata lock. Those locks end before the clone is streamed with one 64 KiB buffer. The editor, input client and Foundation Undo remain live; subsequent edits and saves belong to the original workspace. Marked composition is not forced to commit: its last completed checkpoint is captured. Unsupported cloning fails rather than copying live bytes while holding writers. The export task owns and disposes its temporary clone on success, cancellation and error. Restore requires a fresh destination. External weights and disposable caches are outside the workspace.

Attachment originals and inspection receipts are ordinary workspace files. Image decoding, audio conversion and video playback receive bytes in memory. On-device speech is a platform service whose shared asset is prepared automatically on macOS 26 and later. Shutdown cancels and joins Bloom's preparation task; Apple owns system-managed installation and updates. Portable voice JSON, Markdown and readable chat exports are deliberate user actions.

A voice is a pinned chat. Chat instructions and editable user/assistant messages form its source; Rust compiles those into a model-independent, immutable Voice snapshot. The pinned chat and voice share an identity. Explicit edits preserve previous message versions, model receipts, and voice revisions. Imported voices open as ordinary chats. There is no separate voice editing form.
